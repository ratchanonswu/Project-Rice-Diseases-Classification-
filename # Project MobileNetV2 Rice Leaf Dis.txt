# Project: MobileNetV2 Rice Leaf Disease Classification

## 1. Your Role and Objective

Act as a machine learning engineer working on a university research project.

Build a complete, reproducible MobileNetV2 image classification pipeline for a six-class rice leaf disease dataset.

This is a SEPARATE project from the existing ResNet50 project. The purpose is to compare MobileNetV2 against ResNet50 later through a separate research comparison website.

The MobileNetV2 project must be self-contained, maintainable, reproducible, and compatible with the existing ResNet50 experiment's dataset splits and class order.

## 6. MobileNetV2 Model Architecture

Implement the model using TensorFlow/Keras.

Requirements:

- Input size: 224 × 224 × 3.
- Backbone: MobileNetV2 pretrained on ImageNet.
- `include_top=False`.
- Freeze the pretrained backbone for the initial experiment.
- Apply GlobalAveragePooling2D.
- Add Dense(256, activation="relu").
- Add Dropout(0.3).
- Add Dense(6, activation="softmax").

Use the functional API or an equivalent clear Keras implementation.

The architecture should be comparable to the existing ResNet50 experiment, while using the appropriate MobileNetV2 backbone.

Use:

```python
from tensorflow.keras.applications import MobileNetV2
from tensorflow.keras.applications.mobilenet_v2 import preprocess_input
```

Do not use ResNet50's preprocessing function.

## 7. Image Preprocessing and Augmentation

Use 224 × 224 RGB images.

Apply MobileNetV2 preprocessing exactly once:

`tf.keras.applications.mobilenet_v2.preprocess_input`

Verify that the resulting input values are consistent with MobileNetV2's expected preprocessing.

Use the same augmentation policy as the ResNet50 experiment where appropriate:

- Random horizontal flip.
- Random rotation.
- Random zoom.
- Random translation.

Augmentation must occur only on training data, after splitting.

Do not augment validation or test images.

Do not apply augmentation twice or preprocess images twice.

Use a consistent label mapping across all splits.

## 8. Training Configuration

Use the following initial configuration:

- Optimizer: Adam.
- Learning rate: 0.0001.
- Loss: sparse categorical cross-entropy.
- Metric: accuracy.
- Batch size: 32.
- Maximum epochs: 25.
- Random seed: 42, where practical.
- EarlyStopping: monitor `val_loss`, patience 5, restore best weights.
- ReduceLROnPlateau: monitor `val_loss`, factor 0.5, patience 2, minimum learning rate 1e-6.
- ModelCheckpoint: save the best model according to `val_loss`.

Train using only `outputs/train.csv`.

Use `outputs/validation.csv` for validation.

Never load or use the test set during training, checkpoint selection, early stopping, or hyperparameter tuning.

Save the best model to:

`models/mobilenetv2.keras`

Save the training configuration and actual training history. Record the best epoch and the criterion used to select it.
